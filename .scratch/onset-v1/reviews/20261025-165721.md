## Pending decisions

1. **A lost Submit request can leave the claiming screen frozen.** On the player screen, from the Submit tap the cards and the button are disabled and the hint reads "Judging…" until the broadcast that resolves the claim arrives. SPEC §11 says the freeze is lifted only when the request never reaches the server, so the player can tap Submit again. The code does lift it, but only on the screen that sent the request: if any room update redraws the player screen while that failing request is pending (another player's lockout ending, a join, a No Set call), the redrawn screen freezes itself from the page's memory of the claim and is never told the request failed. Memory says unfrozen, the screen stays on "Judging…" with everything disabled until the next redraw or until the 15-second timer judges the stored picks (which, with three picks stored, gives the same verdict Submit would have, so no point is lost unless the third pick request was lost too). It needs a network failure and a redraw in the same second, so it is rare, and the timer bounds it at 15 seconds. `card_selection_controller.js:118-121`, SPEC `§11`: "The freeze is lifted only when the request fails to reach the server, so the player can tap again".
   - Recommended: fix it in a small ticket, because the spec promises the unfreeze and the fix is a few lines (on a rejected submit, refresh whichever controller is connected for that claim, or let a connecting controller re-check). Cost: one short build, no spec change. Ready to type:
     `/skills-loop:request Behind the scenes: a Submit request that never reaches the server unfreezes the claiming screen even when a room update redrew it while the request was pending (SPEC §11 says the freeze is lifted on a failed request; today only the controller that sent it is refreshed, card_selection_controller.js:120)`
   - Or: accept it, since the timer judges the same three picks within 15 seconds and the case needs two rare events at once. Cost: a rare 15-second wait a player cannot explain; the spec sentence would then need a clause saying the unfreeze may wait for a redraw.
