## Findings

### Standards

- **`CLAUDE.md` line 39 is stale (records drift).** It says "`bin/test-all` names any file over it". Since c4900ae and 57045c1, the script names a file only when it was over 8 s in the last two full runs, and skips the check when the machine is busy or the run is in CI. Plain fix outside the loop (a CLAUDE.md wording edit, no ticket): say "names a file over it in two full runs in a row, unless the machine is busy".
- **`bin/test-all` busy check (tooling, judgement).**
  - In CI a targeted run prints "Machine busy (CPU CI% idle)", which is misleading.
  - `top -l` is macOS-only. On Linux outside CI, `idle` comes back empty and reads as 0, so the slow-file check never runs.
  - The 1 s `top` sample also runs on targeted runs (`bin/test-all spec/...`), where `target` is empty and its result is never read.
  - Plain fix outside the loop: give CI its own message, or none, and sample only when the result is used.
- **Possible Duplicated Code: the player screen's claim lookup.** It is done in two places:
  - `app/controllers/controllers_controller.rb:7`: `@my_claim = @game.current_claim if @game.claim_player_id == @player.id`
  - `app/views/players/_controller_status.html.erb:4`: the same lookup.

  Nothing reads `@my_claim`: the view renders the partial without passing it. Ticket 56 had to edit both copies. Deferred on 56.
- **Possible Duplicated Code: the cookie rule is written in Ruby and JS.** `settings_controller.js#syncFromCookies` hardcodes `"light"`, `"dark"` and `"colorblind"`, the same rule `ThemesHelper::THEMES` and `#chosen_card_colors` hold.
  - Ticket 52 asked for "the same rule as `ThemesHelper#chosen_theme` and `#chosen_card_colors`", and `other_tab_spec.rb` ("sets nothing for a cookie value the server would not accept") would catch the two copies drifting apart.
  - Ticket 50's one-source goal covers hex values, not choice names.
  - Left as it is: it is two short literals with a spec guarding them. Passing them as Stimulus values, the way `themeColors` already is, would add markup for little gain.
- **Possible Data Clumps / Primitive Obsession in `settings_controller.js`.** `store(cookie, key, value, fallback)` takes four strings. The same groups ("theme"/"theme"/"device", "card_colors"/"cardColors"/"classic") come back in `syncFromCookies` and the getters. One `PICKS` map would serve all of them. Not deferred: no user would notice it, and it is not worth a ticket alone.
- **Possible Primitive Obsession in `ThemesHelper`.** `%w[device light dark]` and `"device"` are spelled out in `themes_helper.rb` and `_settings.html.erb`, and `%w[colorblind]` is inline, while `THEMES` is a constant. Minor.
- **`ThemesHelper.theme_color_metas` is a `self.` method** on a view helper, so every caller names the module. Minor. It works and matches how `CardsHelper::COLOR_MARKS` is called.
- **What counts as a running claim is defined two ways.** `vote_end_game!` checks `claim_active?` (is `claim_player_id` set), while pick, submit and expire check `current_claim`. If `claim_player_id` were ever left set with no current claim, End game would stay blocked. Low risk: `try_claim!` and `call_no_set!` already trust the same flag, and SPEC §2 words the End game refusal as "during a claim".
- **Checked and fine:**
  - The `start!`/`restart!` lock nesting under `vote_start!` and `vote_play_again!`: `update!` runs before `lock!` reloads, and a `return` inside `with_lock` commits.
  - The cost of `Game#current_claim`: one indexed `ORDER BY id DESC LIMIT 1`, run at most once per broadcast.
  - The theme-color JSON value is escaped and round-trips. `settings_sources_spec.rb` checks it against the rendered metas.
  - The cookie prefix parsing.
- **Untested.** `Game#current_claim` has no unit spec of its own. Claim, job and request specs cover its four conditions indirectly. Judgement: no follow-up.
